# PUBG 屏幕识别循环（Windows，无边框窗口）

已根据提供的五张截图预置模板，无需首次框选：

| 识别界面 | 动作 |
| --- | --- |
| 大厅“F 游玩” | 按 F |
| 死亡页“回到大厅” | 点击回到大厅 |
| “离开对战”确认弹窗 | 点击确认 |
| 人物结算页“继续”及标题 | 按 Esc |
| 奖励页“关闭”及标题 | 按 Esc |

按当前画面识别，可从任一已知界面开始。界面按钮操作需连续三次识别成功，同一按钮操作至少间隔 12 秒。确认弹窗优先，两个结算页都校验页面标题。

## 跳伞与持续前进

大厅按 F 后先等待匹配，不立即计时。连续 **3 次**检测不到大厅且没有识别到死亡/结算页时，按约定视为已进入房间，从此刻等待 **120 秒**，按一次 F 尝试跳伞，向右转一次视角，然后先按 W、再按左 Shift，保持两键尝试疾跑。跳伞后再等待 **30 秒**，向下压视角至地面，才开始每隔约 **0.5 秒点按一次 F** 尝试拾取；这 30 秒内不重复按 F，避免提前开伞。F 每次都按下并松开，不持续按住。第一次识别到死亡/退出确认/结算界面时松开 W、Shift 并停止点按，再执行返回大厅流程。每一局都重新执行完整流程。

键盘默认改用 Windows `SendInput` 扫描码发送 W、左 Shift、F 等按键，绕过旧方式对虚拟键的映射。持续前进期间每 2 秒重新发送 W 与左 Shift 的按下事件，避免手动松键后脚本仍误以为按住；暂停、切出与结算期间不补发。Windows 接受输入事件不等于游戏一定执行疾跑，仍需实际验证键位、疾跑模式和权限设置。

俯视操作每局只执行一次，默认相对鼠标向下位移 5000，使常规非反转 Y 轴设置下的俯仰角趋向下限。`look_down_pixels` 可调整；反转 Y 轴时使用负值，0 关闭。没有实际落地识别，跳伞后 30 秒为配置指定的时间判断。

右转目标是 **90°**，当前按参考环境实测“位移 900 约转 20°”调整为 `turn_right_pixels: 4050`（900 × 90 ÷ 20）。该换算假设位移与角度近似线性，仍需观察新结果；其他电脑或灵敏度不能保证同样角度。再次校准公式为：新位移 = 当前位移 × 90 ÷ 实测角度。设置为 0 可关闭右转。每局只转一次，暂停恢复及脱困后不会重复转向。疾跑要求游戏的疾跑键绑定为 Shift 且使用按住疾跑的设置。

以大厅消失作为进房间的判断依据，黑屏或加载画面也可能触发；没有识别飞机或实际落地。两个等待时间均可修改 `config.json`：

```json
"movement": {
  "enabled": true,
  "jump_delay_seconds": 120,
  "pickup_enabled": true,
  "pickup_interval_seconds": 0.5,
  "pickup_delay_after_jump_seconds": 30,
  "sprint": true,
  "turn_right_pixels": 4050,
  "look_down_pixels": 5000,
  "keyboard_backend": "scan"
}
```

将 `enabled` 改成 `false` 可关闭跳伞、转向、疾跑和连点拾取，保留自动开始与结算。`sprint: false` 可改回仅按住 W。修改配置后重启程序生效。程序需要先从大厅开始匹配，才会等待大厅消失；在已经进行中的对局启动程序，不会推算跳伞时间。大厅消失的连续帧数沿用 `stable_frames`。

`pickup_enabled` 单独控制连点拾取，`pickup_interval_seconds` 控制点按间隔，默认 0.5 秒。点按计时独立于截图间隔，不会补发暂停期间错过的按键。截图处理和系统负载可能使实际间隔略长；点按 F 不代表已拾取成功或奖励到账。

暂停、切出游戏、正常退出或异常退出的清理流程都会松开 W、Shift 并停止点按。暂停或切出时已经开始的计时仍按真实经过时间计算；回到游戏会先检查画面，若本局已跳伞且仍未识别到死亡/结算，会重新按住 W + Shift，同时遵守跳伞后的 30 秒拾取等待；若尚未跳伞且延迟已过，会尝试跳伞。强制结束进程或电脑断电无法执行清理流程。

## 防卡墙

默认在跳伞动作 **30 秒后**、俯视动作完成后开始检查**右下角小地图**，主画面、人物动作和视角变化不再用于防卡墙判断。根据提供的截图，小地图内部相对范围为 `[0.852, 0.739, 0.980, 0.968]`，按当前屏幕宽高换算，避开上方倒计时、阶段数字及地图边框。地图中央的人物标记和方向提示以圆形遮罩排除，比较的是周围地图地形。

将地图内部缩小为 128×128 灰度图、模糊后分成 **4×4 个块**，与固定基准比较；至少 **85%** 的块平均灰度变化不超过 **2.5** 时视为基本稳定。小地图地形随前进发生连续变化时重置计时；连续两次明显变化确认移动，当前帧明显变化时不会触发脱困。近乎纯黑/纯白区域不参与检测。

置顶状态窗显示防卡墙启用倒计时、稳定累计秒数、稳定分块比例、变化中位数和冷却状态。`bot.log` 每 10 秒记录一次诊断指标，便于区分未启用检测、暂停与画面变化导致的重置。

俯视动作完成后开始采样，小地图地形连续约 **1 秒**基本不变且程序正在按住 W 时，执行以下流程。截图间隔为 0.5 秒，实际触发时间会受处理耗时影响：

1. 暂停 F 拾取，保持向前，尝试 **Shift + C**；C 按约 0.15 秒后松开。
2. 等跨越动画稳定 **2 秒**，再观察小地图约 **3 秒**；连续两次检测到地图地形相对观察基准发生明显变化，视为恢复移动，继续前进并恢复拾取。
3. 如果未检测到持续移动，松开 W 和 Shift，按住 S 后退 **1.2 秒**，再松开。
4. 按住 A 向左横移 **1.5 秒**，再松开；下一次改用 D 向右横移，左右交替。
5. 恢复持续 W + Shift 和原有的 F 点按；仍遵守跳伞后的拾取等待时间。

Shift + C 按配置指定的组合发送，需要游戏键位支持该组合触发跨越。小地图变化只能近似判断位移，缩圈、标记、地图缩放或地图旋转设置仍可能影响结果。`vault_enabled: false` 可跳过跨越尝试，直接使用后退与横移。

一次触发后冷却 **15 秒**，随后重新积累 1 秒静止证据，不会连续执行脱困。动作分阶段计时，不会阻塞死亡识别或停止热键。死亡、暂停、切出游戏或退出时清理 W/Shift/C/S/A/D，暂停恢复后重新检测画面，不继续未完成的跨越/后退/横移动作。

A/D 在默认键位中是横移，不会改变视角。此功能根据小地图地形变化推断卡墙，不读取游戏内部人物坐标；小地图尺寸、HUD 比例、缩放或旋转设置不同，可能导致误判或漏判，可调整 `minimap_relative_rect`。它没有识别实际落地，30 秒仅是可调整的等待时间；尚未真实对局验证。

可修改 `config.json` 的 `anti_stuck`，重启后生效：

```json
"anti_stuck": {
  "enabled": true,
  "check_after_jump_seconds": 30,
  "stationary_seconds": 1,
  "cooldown_seconds": 15,
  "mean_change_threshold": 2.5,
  "stable_tile_fraction": 0.85,
  "minimap_relative_rect": [0.852, 0.739, 0.980, 0.968],
  "motion_confirm_frames": 2,
  "backward_seconds": 1.2,
  "sidestep_seconds": 1.5,
  "vault_enabled": true,
  "vault_settle_seconds": 2.0,
  "vault_observe_seconds": 3.0
}
```

`mean_change_threshold` 越大、`stable_tile_fraction` 越小，越容易将小幅画面变化视为稳定，卡墙检测会更容易触发，也更可能误判。`motion_confirm_frames` 控制需要连续几次大范围变化才重置计时。默认值需根据实测诊断指标调整。将 `enabled` 改成 `false` 只关闭防卡墙。

## 启动与停止

双击 `launch.cmd` 即使用已有模板直接开启自动操作，不需要再次捕捉位置。双击 `preview.cmd` 可仅识别、查看日志，不执行操作。游戏需要在主屏幕并处于前台，切到其他窗口时停止识别和操作。

**F8 只暂停；F7 只继续；F9 停止；Ctrl+C 停止。** 重复按暂停不会继续，重复按继续不会暂停；同时按 F8/F7 时优先暂停。

默认关闭鼠标角落暂停（`mouse_corner_pause: false`），避免右转或向下压视角把光标推到角落而暂停。请使用 F8 暂停、F7 继续、F9 退出。需要角落暂停时可将 `mouse_corner_pause` 改成 `true`，但自动转视角也可能触发它。切到其他窗口时仍暂时释放按键，切回游戏自动继续。

启动后右上方显示**置顶状态窗**：倒计时、当前步骤、最近三条操作记录及暂停原因。窗口鼠标穿透、不抢游戏焦点，在支持的 Windows 上排除出截图识别。退出后显示结束提示约 2 秒并关闭。配置 `"overlay": {"enabled": false}` 可关闭状态窗。独占全屏可能盖住普通置顶窗口，请使用无边框窗口模式。

`preview.cmd` 显示计划执行的跳伞、转向、疾跑及拾取，不实际发送鼠标或键盘操作。

## 在其他电脑使用

使用分发压缩包，解压到普通目录。安装 Python 3.11 或更新版本，安装时勾选 Add Python to PATH，然后双击 `install.cmd` 安装依赖，再打开 `launch.cmd`。首次安装需要联网。不要将当前电脑的 `.venv` 复制到另一台电脑。

手动安装：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

## 相对定位和分辨率

位置按屏幕宽高归一化保存于 `config.json` 的 `relative_rect` 和 `relative_click_point`，运行时按实际截图尺寸换算。模板随当前分辨率缩放，点击前必须识别成功。截图的 2559×1440 是参考尺寸，不是电脑使用限制。

同宽高比采用相对位置与模板缩放；不同比例还尝试按屏幕高度缩放 UI、分别靠左/靠右/居中的布局。识别结果仍可能受游戏语言、UI 比例、主题或版本影响，不能保证所有电脑直接通用。遇到不同界面时重新录制对应模板。

截图缩放测试覆盖 1280×720、1920×1080、2559×1440、2560×1440 和 3440×1440；另有宽屏边缘对齐合成画面测试。这些是离线验证，尚未完成不同电脑的真实游戏验证。

## 重新录制

运行命令后有 5 秒切回对应游戏界面，在静止截图上拖动框选目标按钮文字和边框；Esc 取消。录制时保持参考分辨率，改变整套 UI 尺寸时需删除旧配置并重新录制全部模板。

```powershell
.\.venv\Scripts\python.exe bot.py --capture start
.\.venv\Scripts\python.exe bot.py --capture return_lobby
.\.venv\Scripts\python.exe bot.py --capture confirm
.\.venv\Scripts\python.exe bot.py --capture continue_results
.\.venv\Scripts\python.exe bot.py --capture close_rewards
```

手动录制会替换该状态的模板并移除其旧标题校验。开始和两个结算页仍分别使用 F、Esc、Esc，其余使用识别位置点击。

前台窗口标题默认需包含 `PUBG`。如实际标题不同，可将 `window_title` 改为游戏标题中独有的文字。配置中的阈值默认为 0.90。日志在 `bot.log`。

程序通过按钮判断状态，不直接读取生命值，不核验奖励到账。未录制的弹窗、其他语言、观战界面或不接受普通模拟输入的游戏环境需要进一步适配。
